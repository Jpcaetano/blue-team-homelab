\# Project 01 - pfSense + Snort IDS



\## Overview



This project demonstrates the deployment and validation of Snort IDS on a pfSense firewall inside an isolated Blue Team home lab.



The main goal was to configure Snort on the pfSense LAN interface, enable the Snort GPLv2 Community Rules, create custom detection rules, generate controlled traffic from Kali Linux, and validate alerts generated by Snort.



\## Lab Environment



| Host | Role | IP Address |

|---|---|---|

| pfSense | Firewall / Gateway / IDS | 172.30.2.1 |

| Kali Linux | Testing machine | 172.30.2.100 |

| Metasploitable2 | Vulnerable Linux target | 172.30.2.101 |

| Metasploitable3 | Vulnerable Windows target | 172.30.2.102 |

| Wazuh | SIEM | 172.30.2.104 |



\## Project Goals



\- Configure pfSense as the internal lab gateway.

\- Enable Snort on the LAN interface.

\- Create custom Snort rules.

\## Network Validation



Before testing Snort, basic connectivity was validated from Kali Linux to the pfSense LAN interface and the Metasploitable2 target.



```bash

ping -c 4 172.30.2.1

ping -c 4 172.30.2.101

```



Both tests returned `0% packet loss`, confirming that the internal lab network was working correctly.



\## Snort Configuration



Snort was installed on pfSense using the pfSense Package Manager and enabled on the LAN interface.



The LAN interface was selected because it monitors traffic inside the internal lab network, where Kali Linux and the vulnerable machines are connected.



| Snort Interface | Status | Purpose |

|---|---|---|

| LAN | Enabled | Monitor internal lab traffic |



\## Community Rules



The Snort GPLv2 Community Rules were enabled to provide a baseline ruleset for IDS detection.



Configuration path:



```text

Services > Snort > Global Settings

```



Enabled option:



```text

Enable Snort GPLv2 Community Rules

```



After downloading the rules through the Snort Updates tab, the ruleset was enabled on the LAN interface.



The active rules were validated under:



```text

Services > Snort > Interface Settings > LAN Rules

```



The `GPLv2\_community.rules` category was available and several rules were already enabled by default.



\## Custom Snort Rules



Custom rules were created to detect controlled lab traffic from Kali Linux to Metasploitable2.



```snort

alert icmp 172.30.2.100 any -> 172.30.2.101 any (msg:"LAB ICMP Ping from Kali to Metasploitable2"; sid:1000001; rev:1;)



alert tcp 172.30.2.100 any -> 172.30.2.101 22 (msg:"LAB SSH Connection Attempt from Kali to Metasploitable2"; sid:1000002; rev:1;)



alert tcp 172.30.2.100 any -> 172.30.2.101 80 (msg:"LAB HTTP Connection Attempt from Kali to Metasploitable2"; sid:1000003; rev:1;)



alert tcp 172.30.2.100 any -> 172.30.2.101 21 (msg:"LAB FTP Connection Attempt from Kali to Metasploitable2"; sid:1000004; rev:1;)



alert tcp 172.30.2.100 any -> 172.30.2.101 any (msg:"LAB TCP Traffic from Kali to Metasploitable2"; sid:1000005; rev:1;)

```



These rules were used to validate detection of ICMP traffic, SSH connection attempts, HTTP connection attempts, FTP connection attempts, and general TCP traffic.



\## Traffic Generation



Traffic was generated from Kali Linux against Metasploitable2 using controlled commands.



```bash

ping -c 4 172.30.2.101



ssh 172.30.2.101



curl http://172.30.2.101



nc -vz 172.30.2.101 21



sudo nmap -sS 172.30.2.101



sudo nmap -A 172.30.2.101

```



These tests were executed only inside the isolated local lab network.



\## Detection Results



After generating traffic from Kali Linux, the Snort Alerts page was reviewed.



Snort generated alerts for the custom rules, confirming that the IDS was successfully inspecting traffic on the LAN interface.



| Source | Destination | Activity | Detection |

|---|---|---|---|

| 172.30.2.100 | 172.30.2.101 | ICMP Ping | Snort alert generated |

| 172.30.2.100 | 172.30.2.101 | SSH connection attempt | Snort alert generated |

| 172.30.2.100 | 172.30.2.101 | HTTP connection attempt | Snort alert generated |

| 172.30.2.100 | 172.30.2.101 | FTP connection attempt | Snort alert generated |

| 172.30.2.100 | 172.30.2.101 | Nmap SYN scan | Snort alert generated |

| 172.30.2.100 | 172.30.2.101 | Nmap aggressive scan | Snort alert generated |



The Snort alert export was also saved as a CSV file to preserve the detection results generated during the validation phase.
